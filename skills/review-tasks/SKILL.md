# Review Tasks (Ревью задач)

Цель: финальная проверка задач из поддиректории `tasks` перед кодированием.

Исполнители: AI-агент + субагенты.

## Что проверяется

### Критерий A — Покрытие плана реализации

Для каждого блока работ из `implementation-plan.md` убедиться, что существует одна или несколько задач, явно его реализующих.

Фиксировать: блоки плана без соответствующих задач.

### Критерий B — Отсутствие лишних задач

Для каждой задачи убедиться, что она обусловлена требованием из `implementation-plan.md`.

Фиксировать: задачи, не имеющие обоснования в плане (оверинжиниринг, задачи «на вырост», не запрошенные улучшения).

### Критерий C — Атомарность и независимость

Для каждой задачи убедиться, что:
- Задача реализует один атомарный результат
- Задача может быть выполнена независимо (в рамках заявленных зависимостей)
- Зависимости указаны явно и не являются циклическими
- Задача не требует знаний о деталях реализации других параллельных задач

Фиксировать: задачи, которые фактически зависят от незаявленных задач, или задачи, которые реализуют более одного результата.

### Критерий D — Чёткость и измеримость критериев готовности

Для каждой задачи убедиться, что:
- Раздел «Definition of Done» содержит проверяемые условия (не расплывчатые формулировки)
- Раздел «Acceptance Criteria» описывает наблюдаемое поведение в формате «если X — то Y»
- По критериям однозначно понятно, выполнена задача или нет

Фиксировать: размытые или непроверяемые критерии готовности.

### Критерий E — Полнота описания задачи

Для каждой задачи убедиться, что раздел «Что нужно сделать» достаточно конкретен, чтобы разработчик или агент мог приступить к реализации без дополнительных уточнений.

Фиксировать: задачи с недостаточным описанием действий.

## Классификация замечаний

Каждое замечание получает одну из меток:

- **[КРИТИЧНО]** — блокирует реализацию или приведёт к неверному результату; задачи нельзя принять
- **[ВАЖНО]** — снижает качество или полноту, но не блокирует; требует исправления до утверждения
- **[РЕКОМЕНДАЦИЯ]** — улучшение, которое не блокирует принятие задач

## Формат замечания

```
### [ID] [Краткое описание]

- **Критерий:** A / B / C / D / E
- **Серьёзность:** [КРИТИЧНО] / [ВАЖНО] / [РЕКОМЕНДАЦИЯ]
- **Задача:** task-NNN (или «Общий» для замечаний по набору задач в целом)
- **Описание:** [Что именно не так]
- **Связано с:** `[документ]`, раздел (если применимо)
```

ID формировать как `A-001`, `B-002` и т.д. (буква критерия + трёхзначный номер).

## Как делать

Ты выполняешь роль **супервизора**. Не вычитывай задачи сам — это делают субагенты.

Уточни у пользователя путь к директории фичи (или определи его из контекста), если он неочевиден. Задачи находятся в `<директория фичи>/tasks/`.

Следуй циклу:

### Итерация ревью

**Шаг 1 — Запустить субагентов-ревьюеров**

Для каждого файла задачи в поддиректории `tasks/` запустить отдельного субагента (Agent tool) с инструкцией провести ревью этой задачи.

Передать каждому субагенту:
- Содержимое этого файла **от начала и до строки `## Как делать` — не включая её**
- Путь к файлу задачи для ревью
- Путь к `implementation-plan.md` (для проверки критерия A и B)
- Инструкцию записать результат в файл `tasks/review-task-NNN.md` (рядом с файлом задачи), используя шаблон из `references/task-review-template.md`
- Инструкцию вернуть в ответе: номер задачи и количество замечаний по каждой важности (КРИТИЧНО / ВАЖНО / РЕКОМЕНДАЦИЯ)

Субагентов можно запускать параллельно.

**Шаг 2 — Проверить наличие критических замечаний**

На основе статистики от субагентов-ревьюеров:

- Если ни в одной задаче нет критических замечаний — перейти к **Завершению**.
- Если есть задачи с критическими замечаниями — перейти к Шагу 3.

**Шаг 3 — Запустить субагентов-исправителей**

Для каждой задачи, имеющей критические замечания, запустить субагента (Agent tool) с инструкцией устранить выявленные недостатки. Передать:
- Путь к файлу задачи
- Путь к файлу ревью этой задачи (`tasks/review-task-NNN.md`)
- Путь к `implementation-plan.md`
- Указание: исправить все замечания с меткой `[КРИТИЧНО]` и `[ВАЖНО]`; замечания `[РЕКОМЕНДАЦИЯ]` — на усмотрение

Субагент обновляет файл задачи в соответствии с замечаниями.

**Шаг 4 — Удалить файлы ревью и начать новую итерацию**

Удалить все файлы `tasks/review-task-NNN.md`. Вернуться к Шагу 1.

### Завершение

Когда критических замечаний не осталось:

1. Удалить все оставшиеся файлы `tasks/review-task-NNN.md`.
2. Сообщить пользователю: сколько итераций прошло, сводная статистика оставшихся замечаний (`[ВАЖНО]` и `[РЕКОМЕНДАЦИЯ]`) по задачам.
3. Спросить: «Принимаете задачи или отправить на доработку?»
4. Ждать решения человека. Не коммитить, не выводить commit message, не переносить задачи в completed.

## Язык

Общаться с пользователем на русском. Файлы ревью писать на русском. Технические термины, идентификаторы, имена файлов и код внутри блоков кода — в оригинальном виде (английский).
