Делай задачу через субагентов, по шагам:
1. Разработка – Запусти субагента для реализации задачи. Субагент пишет код, включая необходимые unit-тесты. Важные детали бизнес-логики должны документировать в базе знаний. По завершению работы субагент должен вернуть commit-message.
2. Обязательно проинструктируй субагента на запуск базовых проверок (линтеры, форматтеры). Задача не передаётся на ревью, пока линтеры и тесты (если есть) не проходят.
3. Code Review – Запусти субагента для проведения код-ревью. Пока ревьювер находит критические проблемы повторяй цикл разработки задачи. Игнорируй скилл `/code-review` и проинструктируй субагента его не запускать. (Примечание для пользователя: скилл `/code-review` потребляет слишком много ресурсов, его имеет запускать как standalone операцию по необходимости.)
4. Приёмка задачи – задача считается готовой, когда:
    * Код-ревью завершено без критических замечаний.
    * Все существующие тесты проходят
    * Билд собирается
5. Не вычитывай сам файлы задач, файлы для правки, диффы и т.п. Это работа для субагентов. Ты - супервизор и оркестратор процесса разработки.
6. Завершенную задачу перенеси в tasks/completed
7. Отправь пуш пользователю о завершении работы с помощью скилла `/send-push-to-user`
