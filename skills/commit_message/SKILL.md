Перед тем как сформировать commit message, проверь: если работали с задачей из `.docs/tasks/`, перенеси файл задачи в `.docs/tasks/complete/`. Это обязательный шаг — задача считается завершённой только после перемещения.

**Не запускай git-команды** (`git status`, `git diff`, `git log` и т.д.) для сбора контекста. Ты сам делал изменения — контекст уже у тебя в памяти. Git используется только когда пользователь явно просит закоммитить.

Напиши сообщение коммита на русском языке, которое точно резюмирует изменения, сделанные в данной итерации, следуя лучшим практикам и соглашению о написании коммитов (Conventional Commits), описанным ниже. Коммитить ничего не нужно! Твое сообщение должно выглядеть так (без кодового блока) и быть написано на руссклм языке:

```
<тип>: <суть изменений>

<ТЕЛО (маркированный список)>
```

Пример:

```
(chore): обновление версий библиотек
- Обновлена версия Kotlin с `0.1.0` до `0.2.0`
```

## Рекомендации по написанию сообщений коммитов:
- Пиши четкие, лаконичные и информативные сообщения, объясняющие внесенные изменения.
- Используй изъявительное наклонении, например, "исправляет баг" вместо "исправлен баг".
- Ограничь длину строки в заголовке до 72 символов.
- Не используй заглавную букву в начале заголовка.
- Не ставь точку в конце заголовка.
- Числа и названия файлов обрамляй в обратные кавычки, например, "`0.1`", "`README.md`".
- Ограничь тело сообщения до 256 символов.
- Оставь пустую строку между заголовком и телом сообщения.
- Используй тело сообщения для предоставления контекста или объяснения причин изменений.
- Избегай общих терминов, таких как "обновление" или "изменение", в заголовке. Будь конкретным.
- В заголовке кратко укажи, что сделано, а в теле — зачем и как это было сделано.
- Укажи любые полезные детали в теле сообщения.
- Используй дефис (-) для маркированного списка в теле сообщения.

## Типы коммитов, которые можно использовать:

- build: Изменения, влияющие на систему сборки или внешние зависимости (например, изменения в скриптах сборки: Gradle, NPM, Cargo).
- chore: Разные технические задачи, обновление зависимостей, конфигурации репозитория (примеры scope: проект, зависимости).
- ci: Изменения в файлах и скриптах CI/CD (примеры scope: Travis, CircleCI, GitHub Actions).
- docs: Изменения в документации (например, исправление опечаток или добавление новой документации, примеры scope: Markdown-файл).
- feat: Добавление новой функции.
- fix: Исправление багов.
- perf: Оптимизация производительности.
- refactor: Рефакторинг, который не исправляет баги и не добавляет функции.
- style: Изменения, не влияющие на работу кода (например, пробелы, форматирование).
- test: Добавление или исправление тестов.
